# Phase 0 — Masters Enrichment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enrich track-system's `customers` master with `country` + `contactEmail` + `address` (parity with vendors, which already have them), and add `pg_trgm` + GIN trigram indexes on every party master's `name` — the retrieval substrate the Phase 1 LLM matcher endpoint will query.

**Architecture:** Schema-only enrichment (one Drizzle migration) + extend the existing Mesh sync to persist the three fields it already fetches but currently drops. No behavior change, no cobalt-queue change, no deletion. Vendors are already enriched; forwarders already have domains in `forwarder_aliases`; consignees derive country at query time (Phase 1) — so Phase 0 touches `customers` only.

**Tech Stack:** NestJS 11, Drizzle ORM 0.45, PostgreSQL 16, `pg_trgm` extension, pnpm workspace. Migrations generated by `drizzle-kit generate` (journal-tracked in `backend/drizzle/meta/_journal.json`) and applied by `drizzle-kit migrate` (prod) or the test ledger in `backend/test/setup-db.ts` (auto-applies any new `.sql` in `backend/drizzle/`).

**Spec:** `docs/superpowers/specs/2026-07-09-llm-master-matcher-design.md` §2.

## Global Constraints

- One workspace install at repo root: `pnpm install --frozen-lockfile`. Never `pnpm -C backend ...` (nests a divergent `drizzle-orm`).
- Typecheck: `pnpm --filter backend exec tsc --noEmit -p tsconfig.json`.
- Test: `pnpm --filter backend run test` — backend integration specs need Postgres on `localhost:5432`; the test harness auto-creates + migrates `cobalt_test` on first connect (a NEWLY-ADDED migration auto-applies with no manual `DROP DATABASE`).
- Lint: `pnpm lint` (ESLint flat config) — keep at 0 errors. Style: no semicolons, single quotes, 2-space indent.
- Migrations: edit `backend/src/db/schema/tracking.ts` → `pnpm --filter backend db:generate` → commit the generated `backend/drizzle/00NN_*.sql` + `backend/drizzle/meta/*`. NEVER hand-edit a generated migration's body EXCEPT the sanctioned `CREATE EXTENSION` prepend in Task 1 Step 4.
- Masters are ERP-owned, read-only in-app. The sync NEVER deletes a local row missing from the pull.
